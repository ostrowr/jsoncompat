# GitHub HTTP dispatch import benchmark

Moving HTTP dispatch preparation into codegen reduces full-client bytecode
loading from **0.823 to 0.298 seconds
(64% faster)**. Loading generated source improves from
**1.880 to 1.459 seconds**. All 1,223 emitted operation plans equal the reflective
implementation, with **8,327 → 0** import-time `get_type_hints` calls.

## Import measurements

| Case | Source load, before → after | Bytecode load, before → after |
| --- | ---: | ---: |
| 973 component schemas (control) | 1.076 → **1.086 s** | 0.265 → **0.268 s** |
| 61-operation Issues client | 0.154 → **0.126 s** | 0.079 → **0.046 s** |
| 1,223-operation client | 1.880 → **1.459 s** | 0.823 → **0.298 s** |

These medians measure complete model/API loading after the lightweight package
root, in five fresh Python 3.12.2 processes per mode on macOS ARM64. Source runs
have no generated bytecode; bytecode runs follow `compileall`. Both use the same
release native extension, with the filesystem warm. Baseline `8d107d27` uses its
saved Python runtime and generator; the candidate uses the new runtime and
generator. Builds and tests finish before the sequential measurements begin.
The component-only case has no HTTP dispatch and serves as an unchanged control.

Median full-client bytecode process RSS is
**136.1 → 128.2 MiB**.
Import time excludes interpreter startup and teardown; RSS covers the entire
process. Raw root/load timings, process samples, binary hashes, and type-check
results are in [the measurement data](github-http-dispatch-results.json).

## What moved

Codegen emits request/body field mappings, response header conversion metadata,
Accept values, and escaped literal path segments. It already computes exact,
range, and default success/error partitions for the generated aliases. Those
contracts no longer need to be rediscovered from annotations at import.

Resource modules construct immutable plans alongside their public `OPERATIONS`
metadata. Importing `api.py` checks the plan format, verifies nominal request
identities and duplicate registrations, and publishes the complete mapping
atomically. Binding and first use reuse those plans. Manually declared APIs keep
reflective contract validation. Request encoding, lazy response parsing, status
precedence, `UnexpectedResponse`, and caller-owned transports use the same code.

Invalid parameter/header names, conflicting Cookie parameters, and invalid
literal percent escapes fail generation before publishing files. Metadata and
annotations remain available for users and static type checkers. No public API
option, extra file category, source schema storage, or deferred preparation was
introduced.

Generation uses three fresh output directories per case. Sizes include manifests
and exclude bytecode caches. Full-client output grows by
**1.9%** to store dispatch decisions explicitly;
the file count and all 9,124 model declarations stay unchanged. The largest Python
file remains `operations/repos.py` at **3,294,960 bytes**.
Strict `ty 0.0.86 --error all --python-version 3.12` passes for every generated
file and positive consumer; negative consumers retain their expected argument
and return-type errors.

The component case loads `SimpleUser` (one model); client cases load
`operations.issues` and its dependencies (442 models). Resource imports now also
construct their local dispatch plans without loading other resources.

## Correctness and reproduction

- Every one of the **1,223 full-client** and **61 Issues** operation plans compares
  equal to the reflective implementation, including field order, endpoint
  identity, headers, media selection, Accept values, and path segments. These
  comparisons run in separate processes outside timed imports. The benchmark
  harness records reflection counts and fails if plans differ.
- Independent AST comparison confirms **12,730 validation programs**, model
  declarations, constructors, native conversion/binding plans, public HTTP
  metadata, aliases, and exports are unchanged across the three cases. Only the
  generated dispatch additions and API installation hook differ. All three
  candidate generations are byte-identical; manifest file hashes are verified.
- `just check` passes: Rust and fuzz tests, clippy, strict Python typing, and the
  WASM/site build. All **16 local client integration tests** pass, including
  existing local aiohttp, requests, and sync/async HTTPX examples. The Python
  contract suite contains **50 tests**. The optional public internet smoke test
  was not rerun for this dispatch change.
- Fresh-process tests forbid annotation/dataclass reflection and runtime dispatch
  preparation during generated imports. They cover public API/client aliases,
  model-first and private-identity imports, failed-import recovery, immutable
  registries, and bind/request reuse. Further regressions cover format versions,
  duplicate/cross-API registration, Unicode and percent escaping, parameter-name
  preservation, invalid-contract publication, and all 500 statuses across six
  contracts. The checked-in Petstore goldens are regenerated.

The source and projection rules match the [generation benchmark](github-openapi.md):
GitHub's pinned official OpenAPI 3.1 description, revision
`58b1e0c00b39b9e46c24dc4a0ba6a2669c90e9c1`. The outbound projection excludes two
duplicate path shapes, seven unsupported-media operations, inbound webhooks, and
documentation examples; retained schemas are unchanged.

After building the release CLI and Python extension, use a fresh output directory:

```sh
JSONCOMPAT_NATIVE_PROFILE=release pybindings/.venv/bin/python \
  pybindings/bench_github_openapi.py --case client \
  --output /tmp/jsoncompat-github-dispatch --repeats 5
```

Use `--case issues` and `--case models` with separate fresh directories for the
other cases. The harness records all generated-versus-reflective plan checks
outside import timings. Comparing revisions requires each revision's generator
and Python runtime, with the same native extension for this HTTP-only change.
