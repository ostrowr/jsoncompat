# Readable generated clients and native HTTP body conversion

Generated files now put readable model and operation declarations before compact
private programs. The full GitHub client is **48.28 → 43.90 MiB (9% smaller)**
with the same **1,030 files and 9,124 classes**. Cached API import is effectively
unchanged: **252 → 245 ms**. Generation changes **2.389 → 2.482 s**; the readability
work is not a generation-speed optimization.

The main runtime gain is checked HTTP conversion. A 1,000-item JSON body encodes
in **1.249 → 0.547 ms** and decodes in **2.021 → 0.866 ms**, about **2.3× faster**
for both. These measurements exclude network latency.

The largest full-client Python file remains `operations/repos.py`, reduced from
**3,294,960 to 2,647,378 bytes**. Output sizes include manifests and exclude
bytecode caches. No file categories or public options were added.

Baseline is `5191780a`. Each revision uses its own release CLI, Python runtime,
and matching native extension on macOS ARM64 with Python 3.12.2. Import timing
measures loading models/API after the lightweight package root, excluding
interpreter startup and teardown. Source runs have no generated bytecode;
bytecode runs follow `compileall`; the filesystem is warm. Import and first use
still perform no schema compilation or HTTP dispatch preparation.

An initial sequential run showed substantial timing noise. The table therefore
uses a second, interleaved run: baseline/candidate alternate for every sample,
with their order reversed on alternating samples, three fresh generations per
revision, and five fresh-process imports per mode. Builds and tests finished
before timing. Both complete sample sets, binary hashes, initial direct-import
measurements, and type-check results are retained in
[the raw data](github-readable-clients-results.json). The small cached-import
difference should not be read as a major startup improvement.

The source is the same pinned GitHub OpenAPI 3.1 description and outbound
projection documented in [the generation report](github-openapi.md): two duplicate
path shapes, seven unsupported-media operations, inbound webhooks, and
documentation examples are excluded. Retained schema constraints are unchanged.

## What changed in generated source

- Constructors have explicit typed signatures inside their classes. Separate
  initializer functions, import-time initializer patching, and unused namespace
  arguments are gone.
- Each operation groups its response classes, success/error/result aliases, and
  request. Method/path, summaries, and descriptions appear as safely escaped
  docstrings; model and field documentation is retained.
- Imports come first. Declarations and registries use multiline formatting;
  equivalent literal alternatives share one `Literal[...]`; metadata omits
  arguments equal to runtime defaults.
- Files reference the shared missing sentinel directly. Redundant missing and
  byte aliases, unused imports, self-imports, and wildcard re-exports are removed.
  Identical prepared programs within a module share one emitted value.
- Public metadata precedes a marked private footer. Generated HTTP plans use the
  versioned `jsoncompat.codegen.http` interface instead of private binding class
  names. Runtime aliases remain short unless a model name would collide; API
  identities are imported directly from their defining module.

The [checked-in Petstore client](../../examples/openapi_client/petstore/) and all
model snapshots are regenerated. Operation-specific response/header aliases,
nominal class identity, constructor defaults, dataclass reflection, and typing
remain available.

## Checked HTTP body conversion

| Items | Body bytes | Encode, before → after | Decode + unwrap, before → after | Request + unwrap, before → after |
| --- | ---: | ---: | ---: | ---: |
| 100 | 6,691 | 0.124 → 0.061 ms | 0.194 → 0.084 ms | 0.199 → 0.089 ms |
| 1,000 | 68,791 | 1.249 → 0.547 ms | 2.021 → 0.866 ms | 2.041 → 0.880 ms |
| 10,000 | 707,791 | 12.859 → 5.479 ms | 23.084 → 8.588 ms | 24.939 → 8.556 ms |

The fixture contains nested objects and arrays, required fields, length/range
constraints, and a typed response header. Encoding includes checked `prepare()`;
decoding includes a fresh response envelope and explicit `unwrap()`. The complete
request case uses an in-memory fetcher. Each case calibrates to at least 50 ms
and reports the median of seven repetitions. Setup and semantic round-trip
checks are outside timers. Raw samples, the one-item case, and provenance are in
[the HTTP measurements](http-native-models-results.json).

Fixed-media JSON requests serialize native slots to bytes, materializing only
small non-body parameters. JSON responses parse directly into generated models
without first constructing an intermediate Python body tree. Both validate the
complete envelope. Text and multi-media requests retain value conversion;
precision-sensitive numbers and failed optimized conversions fall back to the
established path to preserve acceptance and diagnostics. Explicit public
conversion overrides are honored. Object parameter and typed-header mapping
order is preserved.

`request()` still buffers the body. Only `.result()` or `.unwrap()` requests
contract parsing, and the decoded result or failure is cached. Unexpected errors
retain their status, headers, exact bytes, and diagnostic helpers.

## Correctness and reproduction

- `just check` passes: Rust/fuzz suites, clippy, strict Python typing, and the
  website/WASM checks and build. The whitespace-only final emitter cleanup also
  has a focused source/docstring/cached-regeneration check.
- All 18 local OpenAPI integration tests pass, including aiohttp, requests,
  sync/async HTTPX, 54 Python contract tests, and strict consumer typing. A new
  native conversion differential test compares values and full error details
  across primitives, exact bounds, rounded/overflowing numbers, unions, arrays,
  additional properties, duplicate keys, invalid/trailing JSON, mapping order,
  and media variants. The optional public internet smoke test was not rerun.
- Strict `ty 0.0.86 --error all --python-version 3.12` passes for every generated
  GitHub file and positive consumer; negative consumers produce the expected
  argument and return-type errors.
- Every emitted plan matches reflective preparation: all 1,223 full-client and
  61 Issues operations, with zero import-time `get_type_hints` calls.
- Independent AST comparison resolves each model's bound program, including
  deduplicated references: all **12,730 programs** across the three cases are
  byte-identical to baseline. Three fresh generations per case are byte-identical
  and manifest hashes match their files.

After building the release CLI and native extension, use fresh directories:

```sh
JSONCOMPAT_NATIVE_PROFILE=release pybindings/.venv/bin/python \
  pybindings/bench_github_openapi.py --case client \
  --output /tmp/jsoncompat-readable-client --repeats 5
JSONCOMPAT_NATIVE_PROFILE=release pybindings/.venv/bin/python \
  pybindings/bench_http_models.py /tmp/jsoncompat-http-models
```

Use `--case models` and `--case issues` with separate directories for the other
GitHub cases. Compare revisions with each revision's generator, Python runtime,
and matching native extension; alternate their sample order to reduce drift.
