# GitHub OpenAPI generation benchmark

Generated models no longer contain source schema JSON. The generator emits
prepared validation programs, conversion plans, and readable model declarations.
There is no schema-storage option, compression path, or runtime introspection
fallback. `Model.__jsoncompat_schema__` is removed; keep the source document as a
build input and regenerate older artifacts with the matching generator.

On the full GitHub client, this reduces generation **4.24 → 3.39 seconds (20%)**,
output **67.65 → 47.38 MiB (30%)**, and full API loading **2.10 → 1.90 seconds
from source (10%)**, or **0.87 → 0.80 seconds from bytecode (8%)**. Direct import
of the Issues resource improves **0.308 → 0.185 seconds from source (40%)**.
The approximately one-second generation target remains unmet.

Each package loses sixteen schema-data buckets and their `__init__.py`. The

from **1.22 GiB to 1.07 GiB**.

from **40 files / 259,819 bytes** to **23 files / 155,052 bytes**, excluding its
ignored build manifest and bytecode caches. Its source/stub/marker golden check
still covers additions, removals, and byte-for-byte regeneration.

## What changed and what remains

Schema JSON previously existed solely for explicit introspection. Removing it
skips pretty serialization, compression, byte-literal rendering, shared-data
indexing, and writing/loading those constants. The runtime no longer creates
schema descriptors or contains a decompressor. Standalone, split-file, and
OpenAPI generators all use the same behavior. The package manifest still
fingerprints the compiler, inputs, and managed artifacts; no new public metadata
or option is needed. Manifest v7 repairs and removes managed files on regeneration,
including obsolete schema-data files, while retaining caller-owned files.

The new full-client primary run spends **1.57 s validating/normalizing schemas**,
**1.01 s preparing/rendering model programs**, and **0.37 s staging source and
exports**. Other contracts, grouping, cache work, publication, and process
startup/teardown account for roughly **0.44 s**. The 0.24-second schema-source
compression phase from the previous profile is gone; output-related work also
shrinks. Validation-program preparation still takes 0.465 s inside rendering.
No validation work moved to imports or first use.

## Correctness

Independent AST-only comparison verifies **all 12,730 prepared validator
programs byte-identical** across the three packages, as well as reachable graph
equivalence. **2,094 modules/stubs** retain identical syntax after removing only
source-schema imports/assignments and the deleted schema argument to
`install_model`. Constructors, HTTP metadata, conversion descriptors, binding
plans, public exports, and aliases match. The verifier reads artifacts without
executing generated code. Its tests reject schema/program/code changes and
exercise source removal under normal and optimized Python.

`just check` passed: full Rust/schema/fuzz suites, model and client regressions,
strict Python typing, clippy, and the WASM/website build. Follow-up package and
round-trip tests passed after test-helper cleanup, including regeneration from
manifest v6 with obsolete data files. Differential tests keep exact generator
inputs as separate temporary fixtures; they do not recover schemas from the
generated classes or round large numeric bounds through Python floats. Local
client integration tests exercise all adapters. The final checked-in client also
passed all ten operations and the error workflows directly with aiohttp, requests,
and sync/async HTTPX. The public JSONPlaceholder test was not rerun for this
generator-only change.

## Method and input

These are new before/after measurements on macOS ARM64 with Python 3.12.2.
Both versions ran sequentially after all builds and tests, using ordinary warm
filesystem caches. Generation medians cover three fresh output directories;
imports cover five fresh processes per mode. Runtime bytecode was prepared
before timing both versions. The baseline uses the preserved release binary and
Python runtime from `366e0766`; no compatibility shim is shipped. The earlier
profile reported 3.95 s; this experiment's fresh control measured 4.24 s, so use
the paired results here when attributing the improvement.

- Official [GitHub REST description](https://raw.githubusercontent.com/github/rest-api-description/58b1e0c00b39b9e46c24dc4a0ba6a2669c90e9c1/descriptions-next/api.github.com/api.github.com.json), revision `58b1e0c00b39b9e46c24dc4a0ba6a2669c90e9c1`.
- SHA-256: `0db1a3dee41ed680628a2a3381a114da7358ac8aa3f7b9276c9198608ca6a1fe`.
- Original: 13,131,466 bytes, 1,232 operations, 973 components, and 274 webhooks.
- The untouched spec remains unsupported because of two duplicate path-template shapes.
- The full-client projection retains 1,223 operations: it omits those two duplicates,
  seven operations using unsupported media, inbound webhooks, and documentation
  examples. Retained schema constraints and response bodies are not simplified.
- The Issues projection retains 61 operations and their model dependencies. The
  component projection clears paths and selects all 973 schemas. Exclusions and
  input fingerprints are recorded in the results.

```sh
cargo build --release --bin jsoncompat
cargo rustc --release -p jsoncompat_py --lib -- \
  -C link-arg=-undefined -C link-arg=dynamic_lookup # macOS

JSONCOMPAT_CODEGEN_TIMING=1 \
uv run --no-config --project pybindings --all-extras --group benchmark --locked \
  python pybindings/bench_github_openapi.py \
  --output /tmp/github-no-schema --case client --repeats 5
```

Use fresh output directories for three generation measurements. `--repeats`
controls import samples. Repeat with `--case models` and `--case issues`; run the
same harness on baseline revision `366e0766` for a paired comparison. Keep the
matching Python runtime for each generator. On other platforms, build the
extension with `cargo build --release -p jsoncompat_py`.

```sh
uv run --no-config --project pybindings --all-extras --locked python \
  pybindings/bench_codegen_equivalence.py \
  --before /tmp/github-before/github_client \
  --after /tmp/github-no-schema/github_client \
  --output /tmp/client-equivalence.json
```
